# Remotion template

A runnable scaffold for the [Remotion engine](../../engines/remotion/ENGINE.md). It is also
that engine's end-to-end fixture: `aiv render template:remotion` runs the whole pipeline on it.

## What it shows

The clip is 5 s at 30 fps (150 frames), 1920x1080 at the `review`/`final` profiles.
- **Frames 0-14: the kit's test card.**
  - The colour swatch strip (`TEST_SWATCHES` at `swatchLayout()` of the render size, from
    `@aiv/core`). `aiv qa` decodes these frames from the final mp4 and checks each patch within
    ±3 code values (`video.json` `qa.swatchFrames`).
  - A grey ramp, crop marks in every corner, and a circle that shows a wrong aspect ratio at
    a glance.
  - The composition declares the same frames as its `swatchFrames` prop. The engine refuses
    to render if the prop and `video.json` disagree.
- **Frames 15-149: a React Three Fiber scene** in the kit's `Stage3D`:
  - a faceted, iridescent chrome icosahedron that reflects a procedural room environment
    (its own `envMap`, brighter than the scene's room light);
  - two glowing rings;
  - a seeded ring of 168 instanced bars that rise and fall. Every property is
    `rand(seed, k, property)`;
  - their shadows on a dark, mostly diffuse floor;
  - an eased camera orbit;
  - bloom and a vignette through the kit's synchronous `PostChain`.
- **On top, DOM:** the title in Inter, a progress bar and a frame counter.
- **Audio:** a quiet D-major sine chord plus seeded brown noise, both generated by ffmpeg
  (`lavfi:` tracks). Remotion's `<Audio>` is not used: `aiv post` mixes and masters audio
  (-14 LUFS).

Every frame is a pure function of `useCurrentFrame()`.

| File | What |
|---|---|
| `video.json` | Engine, entry, composition, format, audio tracks, QA settings. |
| `src/index.ts` | The entry: `registerRoot`. |
| `src/Root.tsx` | The `Main` composition. Its size and fps must match `video.json`. |
| `src/Main.tsx` | Test card, then scene and overlay. |
| `src/Scene.tsx` | The R3F layer. |
| `src/Overlay.tsx` | Title, progress bar, frame counter. |

## Render it

```sh
pnpm aiv doctor --fix                              # once: Remotion's Chrome Headless Shell (~120 MB)
pnpm aiv render template:remotion --profile draft  # 960x540, about 35 s on the reference laptop
pnpm aiv post   template:remotion --profile draft
pnpm aiv qa     template:remotion --profile draft  # then look at out/_template-remotion/qa/draft/contact.png
```

`--profile final` renders 1920x1080 (about 0.3 s per frame here). It also encodes the
YouTube delivery and the archive master, and allows `aiv release template:remotion`. Output
goes to `out/_template-remotion/`, so it never collides with a real video.

## Preview it in Remotion Studio

From the repository root:

```sh
pnpm exec remotion studio templates/remotion/src/index.ts
```

Studio is a preview only. It runs R3F on a wall-clock loop and uses your own browser, so it
hides nondeterminism and can differ in colour. Judge the rendered frames, rendered twice.

A render from Studio's queue (or `pnpm exec remotion render`) uses this repo's headless shell
but does not take the heavy-job lock. An aiv render leaves it alone: the orphan sweep only
kills shells it can attribute to aiv. On this 7.6 GB laptop, do not run both at once.

## Start a video from it

`aiv new <slug> --engine remotion` copies this folder to `videos/<slug>/`, writes its
`video.json` and the stage documents. Then:
1. Replace `src/Scene.tsx` and `src/Overlay.tsx` with your own.
2. Keep the test card frames, or move them. `swatchFrames` in `src/Root.tsx` and
   `qa.swatchFrames` in `video.json` must name the same frames. Without a strip, QA records
   colour as NOT VERIFIED.
3. Replace the `lavfi:` bed with your audio.

Rules for scene code: pose from the frame in JSX props or `useLayoutEffect`, never in
`useEffect` and never with `useFrame`. Post-process only through `PostChain`. Load nothing
from the network. See the kit's [README](../../packages/remotion-kit/README.md).

The template has no `package.json`. `remotion`, `three`, `@react-three/fiber`,
`postprocessing`, `@aiv/core`, `@aiv/remotion-kit` and `@fontsource-variable/inter` resolve
from the repository root, pinned by the lockfile.
